# Working with Daniel

- For issue work, use a separate branch unless Daniel explicitly asks otherwise.
- Before implementing an issue, explain the context, current problem, and proposed approach, then wait for Daniel's approval. Do not start implementation before approval.
- Ask Daniel to make design choices whenever a task may involve them. In particular, leave higher-level design decisions to Daniel rather than deciding or implementing them unilaterally. If a design question arises during implementation, pause and ask before proceeding with the affected choice.
- Keep backend tasks focused on the backend and update the relevant backend documentation as work is completed.
- After making code changes, run the relevant tests before finishing and report the commands and results.
